# NWR-073 Layer Lineage Card

Seed: `NWR-073`

Source question: What lineage record should every design abstraction carry

Evidence layer: application

Claim ceiling: artifact_not_paper_candidate

## Bounded Artifact

This template records how a design abstraction travels from evidence to visual
or product form.

| Field | Purpose |
|---|---|
| abstraction_id | Internal design reference |
| source_anchor | Source or seed that inspired the abstraction |
| evidence_layer | Source-observed, derived, speculative, application, infrastructure, or authority-rights |
| transformation_step | What changed between source and abstraction |
| forbidden_meaning | Meaning the design must not imply |
| review_needed | Human/domain or authority review still needed |

## Evidence Layer

The artifact is application infrastructure. It does not validate any design
meaning.

## Falsification Gate

The card fails if it lets a design artifact imply source meaning without a
traceable transformation step.

## Rights And Authority Guardrail

Product-facing design needs lineage and review before public use.

## What This Teaches Oroma

Every abstraction should carry its ancestry and its forbidden meanings.

## Next Action

Require this card for any design abstraction.
